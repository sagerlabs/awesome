**每次收到新交付后的流程**

1. 记录任务 ID、实现 agent、分支/PR、基础与交付提交；读取任务卡和前置任务的验收记录。没有提交时可以检查本地差异，但不得编造提交或将其计作 dev 已完成。
2. 从当前已获授权的仓库工作区开始，用 `git rev-parse --show-toplevel` 确认根目录；检查 `git status --short`、分支与 HEAD，再 fetch 远端。保留未提交修改；有冲突风险时先用 `git show`/`git diff` 读取精确远端提交，仅在权限允许时使用隔离 worktree 运行检查，不能把脏工作树的测试结果归给目标提交。不强制 reset、覆盖或自动合并用户改动，也不依赖其他 agent 的本机目录。首次审查从 R-0001 基准开始，以后从最近已审查 dev 开始；实际执行时记录完整 commit hash。
3. 对比旧基准、任务分支、目标 dev 的真实差异，确认变更是否确实包含在目标中。重写历史或 cherry-pick 时核对实际内容，不能只依赖提交标题或分支名。明确哪些差异属于任务、额外改动或先前基线问题。
4. 逐条检查任务卡与 A01–A10；跟踪完整调用链和配置/数据来源。对于声称修复的问题，先定位旧触发条件，再验证新结果及相关失败路径，避免只确认新增函数存在。
5. 在目标提交上运行适用检查，记录环境、命令、退出码和证据位置。全仓已有失败与本次新增失败分开；相关验收缺环境时记录待验收，不能按通过计算。无关任务可获得单项通过，但不得因此宣称发布门禁已恢复。
6. 输出按影响排序的发现：优先级、触发条件、实际影响、精确文件/行、复现与修复建议。代码评审的 P0/P1 按具体缺陷严重程度判断；计划中的 P0 表示发布前必做，两者不可机械等同。
7. 对每项给出“未覆盖 / 部分实现 / 需返工 / 分支验收通过 / 待 dev 验收 / dev 验收完成”。只有满足主计划完成条件才改为已完成，并引用本记录 ID；实际部署与线上验证另记环境和 deployment/data release。
8. 更新主计划的状态、阻塞、依赖和下一批可分派 ID。跨模块协议变化同步 ADR；扩大范围则新增任务并调整里程碑，不能把新增工作藏进已完成任务。

审查本身不自动执行生产发布或擅自向其他 agent 发送任务。是否合并、推送或部署按当次用户授权执行。用户说“review 最新 dev”时，可以直接读取并核验最新远端代码，不需要再次询问是否开始审查。

**按变更范围选择验证证据**

| 变更类型 | 必须检查的行为 | 有效证据示例 |
| --- | --- | --- |
| 数据/ID/生成器 | 多形态 ID 一致、空响应/schema 变化、严格引用与 hash、坏候选不覆盖活动包 | 固定正反例、源适配测试、实际生成差异、校验报告 |
| scope/统计/公告 | 当前补丁与历史分离、热修/地区适用性、新鲜度、低样本主链与回退一致 | 假时钟、旧公告/跨赛季/未知 patch/低样本案例 |
| 快照/Graph | NLU、别名、事实、索引共用 release；加载失败不混包；请求期稳定 | 完整快照集成测试、失败注入、相关 race 检查 |
| AppService/协议 | JSON v1 保留语义；SSE 元事件兼容；Web/Wails 生命周期一致 | 旧客户端契约、真实事件序列、取消/错误/历史恢复 |
| 身份/会话/预算 | 所有权、并发 CAS、双实例持久状态、额度只预留一次、超时释放 | PostgreSQL 集成测试、越权与并发请求、重启恢复 |
| UI/反馈 | 实际 DOM 清洗、部分流式输入、有效证据、反馈幂等及版本迁移提示 | 浏览器与适用桌面验证、危险输入、断流重放 |
| CI/部署 | 同一产物清单、完整离线包、非 root 可写状态、配置预检、失败非零 | CI artifact、干净 Linux 部署、失败桩、实际日志与退出码 |
| 应用发布/数据灰度 | 同补丁资格、固定会话路由、转发验证、CAS 发布、撤回、排空及旧槽回收 | 双实例长 SSE、会话迁移、并发 promote/rollback、候选失败演练 |
| 指标/评测/性能 | 事实错误可被检测、稳定/候选归因、统计量充分、首次有用内容、成本 | 确定性评测报告、故意错误样例、负载对比、模型评测配置 |
| 演进 | 满足启动条件与产品边界、兼容迁移、实测收益 | GameState/Policy 案例、图像确认流程或容量 ADR 与后续实施任务 |

常规 Go 变更检查 `go test ./...`、`go vet ./...`；并发变更补相关 `-race`，桌面改动补适用 tag 检查。Python、UI、数据库、容器与 Shell 验证按任务卡执行。检查通过后，只有新改动、失败或未解决疑点才扩大/重复验证；文档编辑不触发无关代码测试。真实模型检查与无网络的确定性测试分别报告。
