**TFT Copilot：Agent 分派任务卡与交付约定**

日期：2026-09-08。请先读取[主计划](DELIVERY_PLAN.md)、[ADR013](architecture-decision-013-versioned-data-release.md)和对应任务卡。这里记录范围与验收，不维护第二套进度状态。实现前核对当前 dev 和前置任务提交，不能一直从最初 `d988472` 开始。

**可直接复制的分派 Prompt**

```text
请在你当前已获授权的 TFT Copilot 仓库工作区完成任务 <任务 ID>。
从当前工作区开始，用 git rev-parse --show-toplevel 确认仓库根目录；
下列路径均相对于该仓库根目录，不依赖统筹或其他 agent 的本机目录。

先读以下文档，再读取任务涉及的实现及项目技能/AGENTS 指令：
- docs/DELIVERY_PLAN.md
- docs/architecture-decision-013-versioned-data-release.md
- docs/AGENT_DELIVERY_GUIDE.md 中对应任务卡
- docs/DEV_REVIEW_LOG.md 的最近已审查基准与未关闭问题

你的职责是完成该任务的实现、相关验证、文档与交付记录。
确认前置任务已在所用提交上成立；缺依赖则记录具体阻塞，可先做独立部分。
优先使用已分配给你的工作区和任务分支，记录基础提交。
需要新建分支时命名为 codex/<任务 ID 小写>-<短名>；
只有当前环境允许且确有需要时才新建 worktree，不以访问其他本机目录为前提。
保留工作区现有未提交修改；不得通过覆盖他人文件来解决冲突。
按 ADR013 保持接口、版本与发布一致性，不扩大成全仓重构。
发现需要改变共享协议时，先给出设计差异及影响，交由统筹协调。

交付时提供：任务 ID、基础/交付提交、分支或 PR、主要改动、
逐条验收结果、实际测试命令和输出摘要、未执行项原因、
兼容/迁移/回滚影响、剩余风险、建议台账状态。
如果尚未提交，明确“本地改动待提交”，不能虚构提交或 PR。
按当前会话授权完成交付；本任务的完成状态由统筹对 dev 进行验收后更新。
```

分派时应让执行者通过共享提交或任务附件取得相同文档版本，并在自己的当前工作区读取。正文和任务卡中的代码路径相对于当前仓库根目录；Markdown 文件链接相对于所在文档目录，代码行号使用 `#L行号`。任务卡中的“新增”仅为建议落点，不代表路径/命令已经存在。

**所有任务共同的完成要求**

- 实际行为覆盖任务卡的正常与失败路径；测试断言业务结果，不只断言实现函数被调用。
- 相关模块接口有兼容说明。新增配置提供默认值、必填/可选语义、示例和校验；不输出密钥。
- 单元测试用稳定 fixture，数据契约测试单独验证当前包；禁止用修改生产数据来适配陈旧测试预期。
- 修改数据生成逻辑时，通过受控脚本生成数据并附差异；不手工修生成 JSON 掩盖源问题。人工 aliases/coach notes 不被批量清空。
- 相关 Go 改动运行 `GOCACHE=/tmp/go-build-cache go test ./...` 与 `go vet ./...`；涉及并发/快照/会话的路径增加有针对性的 race 检查；桌面相关改动运行适用的 desktop tag 检查。
- Python 改动运行适配器/流水线测试；安装所需测试依赖后记录可复现环境。缺 pytest、无数据库、无浏览器都不是“测试通过”，真正与交付相关但无法验证的项保持待验收。
- Shell 改动除语法检查外，用本地桩或容器验证失败退出与产物选择；不在审查过程中擅自连接真实生产服务器。
- UI 改动验证流式、历史恢复、取消、错误和降级；安全渲染覆盖实际 DOM 行为，不能只检查源码存在某个函数名。
- `git diff --check` 通过，交付记录区分新增失败和已知基线失败。非相关任务可以单项通过，但不能因此宣称全仓门禁已恢复。
- 所有任务交付可审查的提交与证据；本指南不是单独的生产部署授权。

**FIX-01：恢复确定性测试基线**

范围：`tft/agent/nlu_data_query_test.go`、相关 fixture 和必要测试辅助；避免与 FIX-02 同时修改爬虫/生成数据。

交付：将现有“金克丝必有阵容”的生产数据依赖移入明确 fixture；补充空英雄/未知英雄/英雄+装备的查询行为。当前赛季的中文 ID 与数量/引用检查进入单独数据契约测试，不删除原业务断言。

验收：`TestQueryNLUData_Basic` 全过；切换测试 fixture 不依赖现场赛季；仓库 Go 测试基线恢复。记录真实模型测试的跳过情况，不能把它们计为模型质量通过。

**FIX-02：规范 ID 与抓取适配修复**

范围：`metadata/tft-meta/get_tftmeta_cn.py`、`tft/data/loader.go` 的 ID 解析、专属适配器测试；受控重新生成受影响数据。业务样本过滤统一由 DATA-03 完成，本任务保留其问题记录。

交付：同名多形态建立稳定 canonical ID，优先选择实际阵容单位；lookup 输入顺序改变不覆盖主实体；兼容 apiName、assetNames、DA 类原始 ID。抓取 None、空对象、字段缺失、错误类型时可解释失败；不要只修一个伊莉丝字符串。

验收：伊莉丝规范 ID 对应实际阵容，中文→规范 ID→中文及实际 ID 查询一致；旧 ID 格式仍可解析；变换 lookup 顺序结果不变；失败抓取不发布/覆盖现有产物。附实际数据差异和独立 fixture，说明 UnifiedStore 补充链路是否影响结果。

**FIX-03：部署脚本的确定产物与失败语义**

范围：`deploy/deploy.sh`、`deploy/publish.sh`、`deploy/build-release.sh` 的调用契约与部署文档；此阶段不实现灰度控制。

交付：明确一个通用发布入口；包路径从参数/构建结果取得，带版本/commit，旧入口可作兼容包装。统一服务配置端口与探测端口语义，不让 PORT 仅影响探测却声称改了服务器配置。移除个人 Python 路径，临时文件使用任务独立目录。

验收：任意新日期/版本的包可部署准备；不会靠 ls newest 误选旧包；缺包、上传失败、安装失败、健康失败均非零且无成功文案；无 sudo/HTTP 工具等前置情况能明确报告。现有 .env 按约定保留。用桩验证，无需为该修复连接生产。

**FIX-04：安全渲染与客户端资源**

范围：前端 Markdown 入口、历史恢复、流式重绘、HTML 模板及安全响应头/资源配置接线；与 CORE-04 的身份改造分开。

交付：统一 HTML 清洗与 URL 协议策略；固定或打包所用渲染依赖，外部资源失败时可用；CSP 与实际资源兼容。在已分配工作区中保护未提交 UI 变更，交付冲突说明。

验收：危险 HTML、事件属性、危险链接在完整与分段流式输入、历史重放中都不执行；合法 Markdown、代码块、中文复制正常；依赖加载失败可回退纯文本；Web/Wails 不因资源策略白屏。

**DATA-01：共享版本/发布契约 v1**

范围：新增 release contracts、JSON Schema、manifest 样例；扩展现有 KnowledgeMetadata；不做线上发布实现。

交付：落地 ADR013 的 scope、manifest、source/files、deployment identity、evidence identity；给出必需/可选能力、字段单位、错误类别与兼容策略。生成器和加载器对同一份 fixture 验证；明确 content hash 与 build run ID，避免自引用。

验收：Python→Go 正常样例互通，未知/不兼容 schema 和非法 scope 拒绝；旧知识接口字段保持兼容；精确 patch 不从赛季或公告标题盲猜。C 确认这份契约后，后续任务均复用，禁止复制另一套 DTO。

**DATA-02：可发布数据的严格验证**

范围：单一权威校验入口、领域验证与 `make data-check` 接线；接线文件与 R 协调。优先复用 Go 加载/领域校验，Python 构建流程消费同一验证结果。

交付：非空/schema/唯一 ID/关联引用/数值与单位/赛季补丁/必需文件/hash/可加载性检查；entity 数量骤变生成报告。涵盖英雄形态、共享装备命名空间、别名、画像、公告和统计，不用 ID 前缀粗暴拒绝合法跨赛季实体。

验收：空文件空目录、截断 JSON、缺实体、反向 ID 冲突、hash 错误、混版本被阻止；正确小包可加载；错误报告可定位文件/字段。未知来源元信息可以被保存但不能获得 current 推荐资格。退出码成为构建门禁。

**DATA-03：事实有效性与统一统计资格**

范围：公告查询、knowledge 查询/Meta 补充、元信息与相关数据适用声明；不批量删除可用于历史查询的资料。

交付：按 scope/effective_at 选择当前补丁事实，显式历史对比；排除 S11 等不适用事实；保留 fetched/window/built 时间区别。统一 SamplePolicy，使基础推荐与 Meta 回退的低样本处理一致。未知精确 patch/热修的统计降级，不用公告更新证明统计已更新。

验收：同一问题 current 模式不混入过期公告；历史模式可查询旧包；137 样本案例不会因回退绕过已声明门槛；新补丁统计积累中仍可返回经验证的基础事实；切换地区生效时间可用可控时钟测试。

**DATA-04：隔离构建与不可变制品**

范围：两个来源适配流程、更新脚本、staging 输出、清单打包、差异/验证报告和原始快照保留；源的实体 ID 使用命名空间。

交付：原始快照→标准化→校验→评测报告引用→不可变包；重试/并发构建不覆盖，活动目录不写；人工数据明确合并优先级。输出精确产物位置与 hash，支持受控本地制品库及之后对象存储。

验收：生成中途失败、重复任务、同时构建、上游空响应都不会污染上一包；同输入语义产物可复现；忽略的旧 `_cn.json` 不会被夹带；可离线从原始快照重建；不同数据源 cluster ID 不被误连接。

**CORE-01：完整运行快照**

范围：runtime 组装、knowledge loader/UnifiedStore、Agent 初始化/Fast NLU、统一配置路径。两个 Store 保持实现兼容，不做全量类型重写。

交付：manifest + 全部知识/别名/词典/派生索引作为一个启动快照；完成加载、校验、组装后才 ready；低层 Reload 全失败时保持旧包，退出生产发布入口。首期一实例一 release，不伪装成已经支持进程内灰度。

验收：外挂目录全部生效；无硬编码别名逃回仓库默认路径；knowledge 损坏不会出现新 metadata+旧 knowledge；并发请求共享只读依赖；Graph 只在启动/快照构建时编译，单请求数据身份可追溯。

**CORE-02：应用服务与证据输出**

范围：新增 AppService、统一请求/结果、Handler、Wails 适配和 SSE 协议；NLU/knowledge 领域边界不倒置。

交付：内部统一 RequestContext/AppResult，贯穿 trace、身份、session、scope、release。保留 v1 JSON `data` 和现有 token/error/done 语义，增量提供 metadata/evidence；若新增完整 JSON answer，写明如何请求而不改变旧调用默认行为。C 先审协议样例，再让 UX 接入。

验收：JSON/SSE 对同一输入使用相同证据/版本；元事件不污染 token 文本；旧客户端可忽略新字段/事件；流式完整/取消/错误都不会重复 RecordAdvice；桌面仍走独立事件传输且复用同一应用能力。

**CORE-03：探针、日志与配置可靠性**

范围：Handler 健康接口、logger 注入、启动配置和 provider 环境变量；与部署模板接线协作。

交付：存活与就绪分离；真实快照/必需依赖/可用能力可见，区分 26 套基础推荐与 53 套全量知识。消除修改 global logger 等级的副作用。统一 ARK_BASE_URL 等 provider 端点、超时配置，不暴露密钥。

验收：必需知识失败→不 ready；声明的基础事实降级可解释；健康接口版本与实际回答一致；禁用知识日志不让 Agent trace 消失；健康轮询不逐次调用付费模型；坏配置启动时明确失败。

**CORE-04：身份、预算和请求生命周期**

范围：访问凭证与会话所有权接口、限制中间件、HTTP 参数、模型调用治理、取消/超时；此任务预留 CORE-05 集中实现。

交付：服务端主体身份、会话所有权、输入/Body 上限、可信代理、按用户额度、模型并发和全局成本预算；可撤销凭证；重试预算与取消传播。进程内额度只能用于显式开发/单实例模式，不能宣称双实例预算成立。

验收：无法读取/覆盖别人的 session；伪造代理/内部头不能绕过限制；超长输入被拒绝；断开取消模型调用并释放槽位；超时/失败有稳定错误类型；共享额度接口能被 CORE-05 原子实现，日志不含秘密。

**CORE-05：共享状态与持久反馈**

范围：PostgreSQL 会话/反馈/集中额度实现、数据库迁移、原 JSONL 导入或兼容读取、反馈报告工具。

交付：身份绑定、30 分钟等可配置 TTL、容量限制、CAS/会话串行规则、request 幂等、完整版本化反馈。数据库按 expand/contract 保持应用回滚兼容；开发内存实现与服务器实现明确区分。

验收：同一会话跨实例/重启保持正确上下文；并发追问不乱序覆盖；两实例同时争用额度不超放；反馈跨重建保留，写失败可观测且不被报告为成功。测试容器下运行迁移、重启、故障；没有数据库条件的结果保持待验收。

**OPS-01：统一门禁与可复现产物**

范围：PR/Release/GitFlow workflows、非变更式检查入口、Makefile、Dockerfile、完整离线包与产物清单。

交付：CI 复用同一校验流程，不跳过 agent；包含 Go/Python/数据契约与适用前端检查，真实模型评测独立运行。输出 amd64/arm64 镜像 digest、完整离线包、commit/build 信息和校验和；无个人路径、开发目录残留和秘密。

验收：干净 checkout 可构建，失败数据阻断产物；相同提交/输入可追溯；下载离线包具备必需安装资产和绑定数据。Linux/macOS 打包差异有验证；CI 的 lint/check 不偷偷 fmt/tidy 改文件；发布流程不依赖可覆盖 latest。

**OPS-02：标准服务器部署**

范围：生产 Compose、systemd 模板、配置预检、只读数据/代码、可写状态、HTTPS 代理与安装文档。

交付：服务器无需 Go/Python 源码构建；统一部署清单；独立服务用户与持久目录；全部 provider 配置可传入；明确 PORT/域名/数据库与首次初始化要求。server 模式数据包固定，不能部署时现场抓最新覆盖。

验收：干净 Linux 或测试容器按文档完成启动、健康/业务验证、重启；反馈可写可留存；缺密钥/错误包/端口冲突失败明确；浏览器流式不被代理缓冲。单实例停机更新的局限需说明，双实例由 OPS-03 实现。

**OBS-01：质量、性能与成本可观测性**

范围：应用指标、发布/反馈事件、dashboard/告警配置与基线报告。

交付：按 app/data/prompt/policy/model/实验维度追踪错误、知识命中、Fast NLU、LLM 次数/token/费用、首次有用信息、完成耗时、持久化失败和 ready 时间。明确计费与时间口径；匿名化/保留周期/访问范围。记录有效反馈会话数与回访，不将继续追问算成满意。

验收：合成请求能从 trace 追到所用数据和反馈；候选/稳定可对比；session/request ID 不成为高基数时序标签；告警能触发/恢复。输出首轮阈值建议与样本不足策略，不虚构线上基线或留存数据。

**EVAL-01：事实评测与回放分层**

范围：固定包与 50–100 条代表案例、回放 Runner/Judge、报告格式和 CI 接线。

交付：覆盖别名/多形态、装备/英雄/羁绊、未知/已删除实体、低样本、混补丁、历史对比、反馈纠正、多轮与取消。确定性事实测试立即进 CI；真实 LLM 质量回放记录模型/配置/成本和波动，关键词规则仅保留为行为观察。

验收：故意插入旧版本事实、错误引用、无证据数字时用例能失败；事实/拒答关键项不被平均分掩盖；HTTP SSE 回放与用户链路一致；人工/模型评审使用明确 rubric。真实 LLM 未运行时仅标确定性层通过。

**OPS-03：应用双实例发布与恢复**

范围：两个槽位的启动/探针/切流/排空/清理、代理、数据库兼容与发布状态记录。

交付：新实例验证后接新请求，旧 SSE 排空；应用、数据和数据库兼容清单；失败恢复到已验证组合；程序与数据目录不原地覆盖。退出协调等待 Shutdown，关闭连接不伪造成功完成。

验收：使用测试流长于原 10 秒退出窗口验证普通发布不误杀；候选加载失败/业务探针失败不切流；切流后失败可恢复；旧程序能读取现有兼容状态。回滚目标不存在或不兼容必须失败明确；单机故障仍是停服边界。为 OPS-04 预留退役前检查：会话迁移和在途排空未结束时不得回收槽位，连续第三次发布遇到占用槽位须报告等待/拒绝。

**OPS-04：数据灰度与控制状态机**

范围：release registry/CLI、Go ReleaseRouter、内部单跳转发、会话绑定、控制 revision、promote/revoke/rollback，与代理/状态接线。

交付：按 ADR013 一实例一 release；先 scope 后固定 subject 分桶，再绑定 session。新会话受新比例影响；在途不换包。稳定/候选可并存，实例 ready 上报绑定具体包。控制更新有幂等 ID、CAS、审计、观察窗口/最小样本与自动暂停规则；阈值来自 OBS/EVAL。

验收：同会话多轮不跳包；5→20→50→100% 演练按规则执行；伪造内部头不能绕权，转发无环且取消可传播，不重复计费；控制端不可用、实例未下载、并发 promote/rollback 行为正确。候选撤回迁移会话与版本缓存；正常退役按 ADR 的会话保留上限、CAS 迁移、在途排空顺序回收旧槽，验证全量切换后的旧会话与连续发布。游戏补丁已切时不会把旧补丁当正常对照组，没有同补丁回退包就显式降级。

**UX-01：可见证据与攻略卡片**

范围：Web/Wails 版本信息、阵容/装备/英雄卡片、来源证据、加载/降级/无结果状态；依赖 CORE-02 的实际协议。

交付：用户一眼看到适用补丁、来源、统计窗口/样本资格；基础事实已更新/统计积累中分开。2–3 个候选与条件，详细解释按需展开；事实、经验与推断区别可见。

验收：卡片全部绑定证据 ID，不凭空生成统计；没有早中期棋盘就不展示虚构过渡；元事件先到/后到、断流、历史重放、窄窗均可用；系统构建版本不误标成游戏版本。

**UX-02：显式反馈与会话迁移体验**

范围：有帮助/事实错误/过期/答非所问/信息不足反馈入口、状态同步、会话过期/撤回/补丁变化提示。

交付：反馈携带 request、release 和 evidence，重复点击幂等；上下文条件可确认/更正；失效会话可解释恢复，不在 UI 保留历史时声称后端仍记得。保留网络失败重试的明确状态。

验收：跨实例提交反馈可查询；不接受冒用他人会话；撤回候选或会话过期后的追问不会无提示引用旧事实；继续追问不自动标“有帮助”。

**PERF-01：确定性快速答案与受控模型成本**

范围：高置信规则/模板、证据缓存、Prompt 体积、调用次数、模型错误降级；不牺牲事实约束换速度。

交付：高频查询先提供有用卡片或确定性答案，模型解释按需；低置信最少澄清。缓存包含 scope/release/语言/策略和所有相关条件，个性化上下文隔离；失败模型不回退为编造事实。记录相同负载/数据前后成本与延迟。

验收：预定事实回归集不退化；撤回/切数据后不能命中过期缓存；取消释放资源；缓存不会跨用户串话；首 token 与首次有用信息分别测量，不能用先输出空白制造“优化”。

**OPS-05：发布演练与内测出口验收**

范围：端到端测试环境、故障注入、操作手册与验收报告，避免为演练修改生产业务语义。

交付：覆盖源失败、空/坏包、错 schema、混补丁、下载中断、加载失败、DB 不可用、并发控制更新、会话迁移、长 SSE、主实例切流、回滚与旧产物保留。至少一次同补丁数据灰度和一次新补丁基础事实切换演练，记录 app/data/控制 revision。

验收：坏候选不能接流；正常在途请求有明确结果；发布脚本状态/退出码符合真实状态；回滚后的请求、会话、缓存与证据一致；无同补丁回退包时按规则降级。给出恢复耗时/损失请求/资源占用实测，不以脚本语法代替演练。完成该任务才能宣布 M3 可运营内测出口通过。

**EVOL-01：结构化学习/复盘状态**

范围：GameState schema、会话状态合并、来源与置信度、缺失字段、UI 确认接线。

交付：阶段、等级、金币、血量、连胜败、棋子/星级、备战席、装备和讨论目标；用户补充/否定的字段有修订版本，不默默把未提供值当 0。使用已结束对局、训练或明确历史场景验证。

验收：多轮补充与纠正得到确定状态；同名形态、缺失值、非法值/重复事件均有测试；状态绑定 evidence/scope，不跨补丁复用旧棋子；无图输入也能完成复盘。

**EVOL-02：独立策略与过渡计划**

范围：从 `prompt_decision.go` 提取 DecisionPolicy、候选评分/适用条件、人工 coach notes、early/middle/final 数据接入与评测。

交付：输入结构化状态+事实，输出候选、理由、风险和缺失信息；LLM 只表达。经验资料独立版本，需注明适用条件；不具备卡池/对手等输入时不声称精确概率/EV。产品定位沿用评估的学习与复盘边界。

验收：代表复盘状态可重复得到符合规则的候选；新上下文能改变适用条件；推断与统计区分；真实有 early/middle 来源才显示，缺失时不编造。和原 Prompt 策略做固定用例对比，记录实际改进与未覆盖场景。

**EVOL-03：legacy 与类型收敛（条件启动）**

范围：legacy routes/parser/graph、重复 Store 查询、进程内强类型接口、MCP/HTTP 外部编解码适配。

交付：先统计调用与列迁移调用方，满足兼容/Sunset 条件后分 PR 退场；保留必要兼容壳。先去重语义/实体，再删除代码；禁止同时重写新主链路和所有数据格式。

验收：迁移前后主链路和 MCP 契约案例一致，旧客户端有明确迁移结果；没有因删除 legacy 导致新 API 数据漏载；输出依赖和内存变化实测。条件不满足保持待启动，而不是强行删除。

**EVOL-04：进程内多快照（条件启动）**

范围：SnapshotProvider 注册表、不可变路由视图、后台构建、引用/租约、淘汰和并发控制。

交付：完整候选构建后进入注册表；请求持有同一引用；路由表原子更新，多版本共存。active 指针不是灰度系统；限制内存/旧版本数量、会话 TTL，撤回优先于普通粘性。

验收：长 SSE 与并发切换全过程不混词典/事实；失败加载保持旧快照；race 检查和压力验证通过；旧快照不提前释放也不永久泄漏；多实例 ready/revision 协议仍成立。与双实例基线比较复杂度和资源收益。

**EVOL-05：图片复盘输入（条件启动）**

范围：用户主动提供的复盘图片、OCR/视觉模型适配、结构化状态转换、置信度与人工修正。

交付：图像只是 EVOL-01 的输入适配器；识别结果先呈现待确认状态，再进入策略。未知单位/低置信装备/坐标问题可修正；不将图片中的文字当系统指令。

验收：代表截图集衡量实体/装备/星级识别、修正成本和总延迟；识别失败可回到文本；敏感图片有保留策略，用户不上传时主功能完整；没有自动对手侦察和未经确认的动态局内操作依赖。

**EVOL-06：容量与下一阶段拓扑（条件启动）**

范围：代表请求构成/长 SSE/多会话/大数据包的负载测试，主机故障影响、容量报告与扩容 ADR。

交付：给出单实例/双实例容量、数据加载内存、DB 压力、转发开销、成本和瓶颈。以实际证据选择纵向扩容、跨主机、集中缓存/额度或独立入口；若考虑 Redis、Kubernetes、服务拆分或向量检索，明确它解决的具体指标问题。

验收：可复现实验、预算与失效边界；形成明确 go/no-go 决策及新的实施/验证任务。报告本身不等于已上线 HA；新增基础设施实施由主计划扩展范围与依赖后继续。
